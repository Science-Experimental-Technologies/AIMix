# AIMix Governance

## Principles

AIMix is developed in the open with an emphasis on user safety, provider neutrality, compatibility, reproducibility, and evidence-backed claims.

## Roles

- Contributors propose changes, review work, and improve documentation or tests.
- Maintainers triage reports, review changes, manage releases, and protect project boundaries.
- Release maintainers may publish signed artifacts and coordinate security fixes.

Role assignment is based on sustained, trustworthy contributions. Repository owners retain final responsibility for access and legal decisions.

## Decisions

Routine changes are decided through review. Significant changes—public API breaks, data migrations, licensing, security architecture, or governance—should include a written design and migration plan. Maintainers seek consensus; when consensus is not practical, the responsible maintainer documents the decision and rationale.

## Releases

Releases follow semantic-versioning intent while the project remains pre-1.0: minor versions may introduce carefully documented compatibility changes, and patch versions should remain backward-compatible. Security releases may use an accelerated private-review process.
